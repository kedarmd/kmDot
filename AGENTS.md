# AGENTS.md

Dotfiles for a CachyOS + Hyprland workstation. Config files (not application code) — no build, no tests, no CI.

## Sync Model (Required)

- **Source of truth** is this repo: `config/`, `theme-switcher/`, `themes/`, `sync/`.
- **Never write directly** to `~/.config/*` or `~/.tmux.conf`. Edit the repo, then run `sync/<app>.sh`.
- Sync scripts (e.g. `sync/tmux.sh`) `rm -rf` existing config, `cp -r` from repo, then `ln -sf` to standard locations. Destructive.

## Commands

| Action | Command | Notes |
|---|---|---|
| Install selected apps | `./install.sh` | Requires `gum` (`pacman -S gum`). Multi-select TUI. |
| Single-app sync | `./sync/<app>.sh` | E.g. `./sync/nvim.sh`. Skips the TUI picker. |
| Uninstall | `./uninstall.sh` | Also requires `gum`. Removes symlink targets + kmdot copies. |
| Switch theme (CLI) | `theme-switcher/main.sh <theme>` | Themes: catppuccin, everforest, nord, onedark, tokyonight |
| Switch theme (quickshell launcher) | `config/quickshell/scripts/toggle.sh kmdot-theme` (Super+T) | Picks theme via quickshell launcher, calls `main.sh` (which restarts quickshell once) |
| Quickshell sync | `./sync/quickshell.sh` | Bar config lives in `config/quickshell/`. |

## Adding an App

1. Create `config/<app>/` with config files.
2. Create `sync/<app>.sh` (copy + symlink pattern — see existing scripts).
3. Add to `APPS` array in `install.sh` (and `uninstall.sh` if supported).

## Adding a Theme

1. Create `themes/<theme>/` with per-app config files matching each hook in `theme-switcher/hooks/`.
2. Theme hooks read from `~/.config/kmdot/themes/<theme>/`, not the repo directly.
3. Theme hooks reload the app after writing the config (e.g. `tmux source-file`).

## Key Quirks

- **Tmux**: prefix `C-s`; modular config in `config/tmux/conf.d/` (`00-base`, `10-bindings`, `20-theme`, `90-plugins`); TPM for plugins; UTF-8 locale required for Nerd Fonts.
- **Neovim**: lazy.nvim plugin manager; entrypoint `init.lua` → `require("options")` + `require("config.lazy")`.
- **Wallpapers**: theme-specific in `themes/<theme>/wallpapers/`; `cycle_wallpapers.sh` exits early if hyprpaper isn't running; active theme cached in `~/.cache/kmdot_theme`.
- **Quickshell**: top bar in `config/quickshell/`; colors are a `pragma Singleton` (`Colors.qml`, tokyonight default) regenerated from `themes/<theme>/quickshell.conf` by `theme-switcher/hooks/quickshell.sh`. That hook **restarts quickshell once** on theme change (Colors.qml is written first, then `pkill` + relaunch via `setsid nohup`), so the bar AND the launchers re-theme together and the launcher socket servers re-bind — live-reload on Colors.qml change would re-theme the bar but break the launcher sockets (they don't re-bind on reload), forcing a lazy restart on the next open. Not autostarted previously — autostart now launches `quickshell &`. Install with `sudo pacman -S quickshell` (cachyos-extra-v4).
- **Quickshell launcher**: Super+Space opens the app launcher on Overlay layer. All launchers are thin subclasses of `config/quickshell/components/LauncherBase.qml` (generic single-pane picker: search box, scored results list, footer, socket toggle, dim+card in ONE `PanelWindow` surface — see below for why). The card lives in the same surface as the dim so it can never be covered by it (layer-shell stacking of separate surfaces is creation-order dependent; separate dim windows ended up on top). `FloatingWindow` does NOT work for overlays (it maps as a normal tiled client). Launcher instances (declared in `shell.qml`, coordinated by `property var activeLauncher` so opening one closes the other):
  - `AppLauncher.qml` — sock `kmdot-launcher` (Super+Space). Search is a per-field matcher over `DesktopEntries.applications` (populates ~2s after launch; apps async — rebuild on signal): substring OR fuzzy-subsequence on `name`/`genericName`, substring-only on `execString`/`keywords`/`comment`/`id`. Do NOT fuzzy-match over fields concatenated into one haystack (a query like "files" then matches 21 apps by spanning unrelated words). Non-string entry fields crash `.toLowerCase()` with `TypeError: Property 'toLowerCase' of object is not a function` — string-coerce with `toStr()` (the old `(x || "")` guard does NOT catch non-string objects).
  - `menu/KmdotLauncher.qml` — sock `kmdot-kmdot` (Super+K): Applications / Connections / Keybinds / System / Themes. Nested launchers open via the coordinator.
  - `menu/SystemLauncher.qml` — sock `kmdot-system` (Super+Esc): Lock / Logout / Restart / Shutdown / Suspend (runs `hyprlock`, `hyprctl dispatch 'hl.dsp.exit()'`, `systemctl …`).
  - `menu/ConnectionsLauncher.qml` — sock `kmdot-connections`: Bluetooth (opens `bluetoothLauncher`) / Wi-Fi (opens `wifiLauncher`).
  - `menu/WifiLauncher.qml` — sock `kmdot-wifi` (bar Network module left-click): `nmcli` scan via `Process` + `SplitParser` (fields parsed right-anchored so SSIDs containing `:` survive; `nmcli -t` escapes them), active-first/signal-sorted list with block-glyph signal bars. Wi-Fi on/off is a **footer pill** (right-aligned, `footerActionActive` → `Colors.success` when on; triggered by click OR Tab), NOT a list item — toggling keeps the launcher open (optimistic `_state` flip, re-scan after 1.2s) and, since the radio caches APs lazily after re-enable, empty scans retry up to 2× at 2.5s before showing `emptyText`. While the scan is in flight the launcher shows the `loading` spinner + `loadingText`. Activate: active net → disconnect, saved net → `nmcli connection up`, open net → `nmcli dev wifi connect`, secured unsaved net → **password prompt** (LauncherBase `promptMode`: search input becomes a masked field, list swaps for a centered prompt; `connectProc` runs with `2>&1` into `SplitParser`, on non-zero exit re-prompts with the error). Uses `closeOnActivate: false` since the prompt flow must not close the launcher.
  - `menu/BluetoothLauncher.qml` — sock `kmdot-bluetooth` (bar Bluetooth module left-click): driven by the **native reactive `Quickshell.Bluetooth` service** (no Process/scan — unlike wifi). List from `Bluetooth.devices.values` sorted connected → paired → unpaired, subtitle shows Connected/Paired/Not paired (+ battery % when `batteryAvailable`), glyph mapped from the device's BlueZ `icon` string (`input-keyboard`→`\uf11c`, `input-mouse`→`\uf245`, audio→`\uf025`, phone→`\uf10b`, computer→`\uf109`, video-display→`\uf26c`, default→`\uf293`). Adapter power is the same **footer pill** pattern (`\uf293` on / `\uf011` off) — Tab toggles `adapter.enabled` (reactive, no optimistic flip needed). Discovery auto-starts on open and stops on close via the `onOpenedChange()` base seam (LauncherBase calls it on every `opened` change; subclasses must NOT re-declare `onOpenedChanged` or they shadow the base's focus-timer handler). Activate: connected → disconnect, paired → connect, unpaired → `pair()` then **auto-connect** once `paired` flips true (`_pairInFlight` set keyed by `dbusPath`, dropped on pair failure). Reactivity via `Connections` on `defaultAdapterChanged`/adapter `enabledChanged`+`discoveringChanged` (no `devices.countChanged` exists — the model is an `UntypedObjectModel` with no count signal; the pool refreshes at discovery start/stop transitions) plus per-device dynamic `d.<prop>Changed.connect(rebuild)` wired once in `rebuild()`. **blueman stays installed solely as the BlueZ pairing agent** (quickshell's service has NO agent support — PIN/passkey-confirming devices need blueman-applet running); bar + Connections no longer launch `blueman-manager`.
  - `menu/KeybindsLauncher.qml` — sock `kmdot-keybinds`: display-only (`deactivatable: false`) listing parsed from `config/hyprland/scripts/keybinds.lua` (a Lua shim that stubs `hl` and prints `KEY + combo   comment` from `keybinds.lua`).
  - `menu/ThemeLauncher.qml` — sock `kmdot-theme` (Super+T): lists themes via `Process` + `SplitParser` (NO `DirListing` API exists) from `scripts/list-themes.sh` (marks the active theme from `~/.cache/kmdot_theme`), runs `theme-switcher/main.sh <theme>` **detached** (`setsid nohup … </dev/null`) — mandatory: the quickshell hook pkills quickshell mid-run, and a live stdout pipe to a dying parent would SIGPIPE `main.sh` (`echo: write error: Broken pipe`). `refreshItems()` rebuilds `pool` on every open.
  - `modules/Backlight.qml` — brightness with an **optimistic + coalesced** setter (spawning a shell process per wheel tick drops steps, so scroll felt janky vs the Pipewire-based volume module): wheel updates the cached `cur` immediately for a smooth display, a single `Process` applies `brightnessctl set <target>`, and while a set is in flight the latest target is remembered (`_pending`) and applied on `onExited` so fast scrolls converge without dropping the last step; the 500ms poll only adopts the actual value when no set is in flight.
  - `LauncherBase` seams: `promptMode`/`startPrompt(title, error)`/`promptSubmitted(text)`/`exitPrompt()` turn the search input into a password field with a centered prompt + error line (footer hint + lock glyph swap in automatically); `closeOnActivate: false` makes `activate()` keep the launcher open so a subclass can decide (e.g. wifi password flow); `loading`/`loadingText` swap the `emptyText` ("No matches") for a spinner + message while the pool is being (re)built; `footerActionText`/`footerActionGlyph`/`footerActionActive` render a right-aligned footer pill that emits `footerActionClicked()` (Tab also triggers it — other launchers leave `footerActionText` empty; the footer hint elides to reserved space so it never runs underneath the pill, and the count text only takes its content width with a growing spacer pushing it to the right edge); `onOpenedChange()` is called on every `opened` change (subclasses use it to start/stop work tied to visibility, e.g. bluetooth discovery — do NOT re-declare `onOpenedChanged` or you shadow the base's focus-timer handler).
  - Toggled via a unix socket at `$XDG_RUNTIME_DIR/<sockName>.sock` (`SocketServer` + `handler: Socket { onConnectedChanged }` — note `onNewConnection` is a method, not a signal). All keybinds + bar clicks call `config/quickshell/scripts/toggle.sh <sockname>` (the app launcher alias is `launcher.sh`). `toggle.sh` **self-heals** if the socket is missing OR stale (file present but no server listening — quickshell died, or a live-reload from a manual Colors.qml edit unlinked the socket; the server won't re-bind on live-reload): `pkill -x quickshell`, restart via `setsid`, wait for the socket to accept, then connect. A normal theme switch restarts quickshell in the hook, so self-heal is now a backstop.
  - `Quickshell.iconPath()` returns a working `image://icon/` URL usable in `Image`; `IconImage` is NOT available in this QtQuick. Delegate rows render a nerd-font `Text` glyph OR an `Image` icon (one or the other). Page keys: `Keys.onPressed` + `event.key === Qt.Key_PageUp/Down` (no dedicated handlers). Do NOT set `clip: true` on the card rectangle or the bottom corners square off — clip only the `ListView`. If the socket gets stale (previous instance died), `rm $XDG_RUNTIME_DIR/kmdot-launcher.sock` and restart quickshell — the server won't re-bind on live-reload.
- **Waybar & rofi fully removed**: the quickshell bar replaced waybar and the quickshell launchers replaced rofi, so both apps were uninstalled (`sudo pacman -Rns waybar rofi`) and every trace is gone — no `config/waybar/`, `config/rofi/`, `sync/waybar.sh`, `sync/rofi.sh`, theme hooks, or theme files (`themes/<t>/waybar.css`, `rofi.rasi`), and the Super+R/H waybar keybinds were deleted. `config/quickshell/` is the single source for the bar and all menus.
- **Gitignored**: `config/fish/secrets.fish`.
- **OpenCode theme hook**: writes the `theme` key to `~/.config/opencode/tui.json` (and `~/.local/share/opencode/kv.json` if present, since the `/themes` runtime pref can otherwise override it) via `theme-switcher/hooks/opencode.sh`. Applies on next opencode launch (no live reload).
- **Zed theme hook**: rewrites the top-level `"theme"` key (as a scalar, never touching `icon_theme`) in `~/.config/zed/settings.json` via `theme-switcher/hooks/zed.sh`. It writes **in place** (`cat >`, same inode) so Zed's settings watcher hot-reloads it live — no restart needed. Themes come from the catppuccin/everforest/nord/tokyo-night extensions (onedark uses built-in One Dark); see `themes/<theme>/zed.conf`.
