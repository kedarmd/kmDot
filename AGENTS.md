# AGENTS.md

Dotfiles for a CachyOS + Hyprland workstation. Config files (not application code) — no build, no tests, no CI.

## Sync Model (Required)

- **Source of truth** is this repo: `config/`, `theme-switcher/`, `themes/`, `sync/`.
- **Never write directly** to `~/.config/*` or `~/.tmux.conf`. Edit the repo, then run `sync/<app>.sh`.
- Sync scripts (e.g. `sync/tmux.sh`) `rm -rf` existing config, `cp -r` from repo, then `ln -sf` to standard locations. Destructive.

## Runtime Requirements

- **No Python or other interpreted languages.** This repo is deployed across all devices; Python is NOT guaranteed to be installed. Scripts must be bash (`#!/usr/bin/env bash`) or **JavaScript (Node) — the only exception** (Node is installed everywhere, e.g. `calendar-events.mjs`, the `toggle.sh` socket connect). Prefer bash whenever it can express the task; use Node only when bash can't. Never add `.py`/`.rb`/`.pl`/etc. — the old `server-mode-watcher.py` and the `python3` socket connect in `toggle.sh` were both removed for this reason. Prefer config-only solutions over code where possible.
- **Scripts must be executable.** Files written by an editor default to 0644, which breaks anything that spawns a script by path (a script run under `systemd-inhibit` once exited `status=1/FAILURE` because it wasn't `+x` — no sleep lock AND no screen dim). `sync/quickshell.sh` runs `chmod +x scripts/*.sh` as a safety net; if you create a new script, `chmod +x` it in the repo.

## Commands

| Action | Command | Notes |
|---|---|---|
| Install selected apps | `./install.sh` | Requires `gum` (`pacman -S gum`). Multi-select TUI. |
| Single-app sync | `./sync/<app>.sh` | E.g. `./sync/nvim.sh`. Skips the TUI picker. |
| Uninstall | `./uninstall.sh` | Also requires `gum`. Removes symlink targets + kmdot copies. |
| Switch theme (CLI) | `theme-switcher/main.sh <theme>` | Themes: catppuccin, everforest, nord, onedark, tokyonight |
| Switch theme (quickshell launcher) | `config/quickshell/scripts/toggle.sh kmdot-theme` (Super+T) | Picks theme via quickshell launcher, calls `main.sh` (which restarts quickshell once) |
| Quickshell sync | `./sync/quickshell.sh` | Bar config lives in `config/quickshell/`. |
| Server mode (icon in hidden tray, right group) | hover the chevron (before Wi-Fi), click the server icon | Toggles the headless-server mode (see Key Quirks). |
| Install polkit rule (one-time, sudo) | `sudo install -Dm644 config/polkit/90-kmdot-server-mode.rules /etc/polkit-1/rules.d/` | Lets the bar start/stop tailscaled/jellyfin/docker/containerd without password prompts. |

## Adding an App

1. Create `config/<app>/` with config files.
2. Create `sync/<app>.sh` (copy + symlink pattern — see existing scripts).
3. Add to `APPS` array in `install.sh` (and `uninstall.sh` if supported).

## Adding a Theme

1. Create `themes/<theme>/` with per-app config files matching each hook in `theme-switcher/hooks/`.
2. Theme hooks read from `~/.config/kmdot/themes/<theme>/`, not the repo directly.
3. Theme hooks reload the app after writing the config (e.g. `tmux source-file`).

## quickshell.conf color roles (M3 mapping — MUST use canonical theme swatches)

Every theme's `themes/<theme>/quickshell.conf` feeds `Colors.qml` (via the quickshell hook, which auto-emits every `key=value` line as `Colors.<key>`). The keys are M3 semantic roles, NOT arbitrary names — assign each the theme's **real canonical swatch**. Rule of thumb: `base`/`surface` come from the theme's darkest background stack; `primary`/`primary_alt`/`accent` are the theme's distinct accent colors; active/selected surfaces use a dark **tonal container** with light `on_primary_container` text (never dark text).

- `base` = deepest bg (footer) · `surface` = TRUE main background (**top bar**) · `surface_alt` = first elevated surface (hover) · `surface_high` = card bg (launchers/popups) · `surface_highest` = search bar / highest elevation
- `text` = main fg · `text_alt` = secondary fg · `muted` = comment/gutter gray
- `primary` = theme's primary accent (blue/lavender) · `primary_alt` = secondary accent (mauve/purple/blue) · `accent` = tertiary accent (cyan/teal/mauve) — must differ from `primary_alt`
- `success`/`warning`/`error` = green/yellow/red
- `primary_container` = theme's official selection/visual bg (active/selected fill) · `on_primary_container` = light fg on it
- `divider`/`outline_variant`/`border` = theme's border/comment gray

Canonical source per theme: TokyoNight `folke/tokyonight.nvim` (night), Catppuccin `catppuccin/catppuccin` (mocha), Everforest `sainnhe/everforest` (dark hard), Nord `nordtheme.com`, One Dark `atom/one-dark-syntax`. **One Dark caveat**: its palette is compressed, so `surface_high`/`surface_highest`/`primary_container` all use the real selection `#3E4452` to keep canonical `#ABB2BF` text ≥4.5:1 (the brighter `#4B5263` drops to ~3.7) — the search bar is still distinguished by its primary focus border. Nord has a flat polar-night base: `base`/`surface` are both `nord0`.

## Key Quirks

- **Tmux**: prefix `C-s`; modular config in `config/tmux/conf.d/` (`00-base`, `10-bindings`, `20-theme`, `90-plugins`); TPM for plugins; UTF-8 locale required for Nerd Fonts.
- **Neovim**: lazy.nvim plugin manager; entrypoint `init.lua` → `require("options")` + `require("config.lazy")`.
- **Wallpapers**: theme-specific in `themes/<theme>/wallpapers/`; `cycle_wallpapers.sh` exits early if hyprpaper isn't running; active theme cached in `~/.cache/kmdot_theme`.
- **Quickshell**: top bar in `config/quickshell/`; colors are a `pragma Singleton` (`Colors.qml`, tokyonight default) regenerated from `themes/<theme>/quickshell.conf` by `theme-switcher/hooks/quickshell.sh`. That hook **restarts quickshell once** on theme change (Colors.qml is written first, then `pkill` + relaunch via `setsid nohup`), so the bar AND the launchers re-theme together and the launcher socket servers re-bind — live-reload on Colors.qml change would re-theme the bar but break the launcher sockets (they don't re-bind on reload), forcing a lazy restart on the next open. Not autostarted previously — autostart now launches `quickshell &`. Install with `sudo pacman -S quickshell` (cachyos-extra-v4).
- **Quickshell launcher**: Super+Space opens the app launcher on Overlay layer. All launchers are thin subclasses of `config/quickshell/components/LauncherBase.qml` (generic single-pane picker: search box, scored results list, footer, socket toggle, dim+card in ONE `PanelWindow` surface — see below for why). The card lives in the same surface as the dim so it can never be covered by it (layer-shell stacking of separate surfaces is creation-order dependent; separate dim windows ended up on top). `FloatingWindow` does NOT work for overlays (it maps as a normal tiled client). Launcher instances (declared in `shell.qml`, coordinated by `property var activeLauncher` so opening one closes the other):

Delegate rows render a nerd-font `Text` glyph OR an `Image` icon (one or the other). **Glyph footgun**: QML `\uXXXX` string escapes take EXACTLY 4 hex digits — a 5-hex codepoint like `\uf075f` silently renders as U+F075 (fa-comment) + a literal `f`, and `\uf00de` renders as fa-xmark + `e`. PUA glyphs with 5 hex digits (e.g. md-bluetooth U+F00AF, md-volume_high U+F057E, md-brightness U+F00DE+; `md-volume_mute` U+F075F in `Audio.qml`) must be embedded as the **literal Unicode character**, or use 4-digit codepoints instead (`\uEEE8` fa-volume_xmark, `\uf026` fa-volume_off). Page keys: `Keys.onPressed` + `event.key === Qt.Key_PageUp/Down` (no dedicated handlers). Do NOT set `clip: true` on the card rectangle or the bottom corners square off — clip only the `ListView`. If the socket gets stale (previous instance died), `rm $XDG_RUNTIME_DIR/kmdot-launcher.sock` and restart quickshell — the server won't re-bind on live-reload.
  - **`on*` property-name footgun (caused a multi-session "dark text" bug)**: a QML property whose name matches `on` + UPPERCASE (e.g. `onPrimaryContainer`, `onError`) is parsed as a **signal handler**, never as a property — the declaration compiles silently (or hard-fails with `Cannot assign a value to a signal` when the value is a literal), the property simply doesn't exist, and every consumer binding falls back to **default black**. This is why `Tokens.qml` uses snake_case token names (`on_primary_container`, `on_error_container`, …) — `on_` + lowercase is safe. All `on_*` tokens are LIGHT (`Colors.text`-family) — never introduce a dark `Colors.base` "on" color; every active/selected/connected surface in this config is dark-filled with light text. Also: in the Workspaces delegate the Rectangle must reference its own `active`/`urgent` unqualified — `parent.active` resolves against the Row (no such property) and the active workspace silently loses its fill.
- **HiddenModules tray** (`modules/HiddenModules.qml`): a chevron (`\uf104`, flips to `\uf105` when open) at the START of the right group (before Network/Wi-Fi). Hovering it slides it LEFT (width `NumberAnimation`, 180ms OutCubic) revealing the hidden modules INLINE in the bar to its right — NOT a popup card. Leaving the tray collapses it (150ms grace timer). Hidden modules are declared INLINE as children via `default property alias modules: modulesRow.data`, so future modules are just another child in shell.qml. **Reusable popup lock**: a `stayOpen` property pins the tray open while a hidden module's dropdown/menu is open — bind it in shell.qml (`stayOpen: <popup>.opened`); the tray only collapses when `stayOpen` is false AND the pointer has left it (the `onStayOpenChanged` handler stops the close timer on lock, restarts it on unlock; the close timer itself checks `stayOpen`). The chevron itself is a plain `Text` (not clickable); a full-cover `MouseArea` with `acceptedButtons: Qt.NoButton` + `hoverEnabled` tracks enter/exit for the whole tray while letting clicks fall through to the modules. `clip: true` on the root so the hidden modules don't render past its closed bounds; the modules row is also `enabled: root.open` so a closed module can't intercept input.
- **Server Mode**: turns the laptop into a headless part-time server (Tailscale + Jellyfin) via the `modules/ServerMode.qml` icon (fa-server `\uf233`), which lives INSIDE the HiddenModules tray (NOT in the center group). Clicking the server icon only opens/closes `menu/ServerModeDropdown.qml` (sock `kmdot-server`; positioned under the icon via `mapToGlobal` + the dropdown's `cardX` clamp; a second click closes it). The tray stays open while the dropdown is open via the `stayOpen` lock (`stayOpen: serverModeDropdown.opened` in shell.qml) — the chevron only slides back when the menu closes. Mode toggling happens ONLY via the dropdown's toggle pills (a bug once auto-toggled on open via `toggleServerMode()` — removed). There are two side-by-side pills: **Turn On/Turn Off** (full mode incl. services) and **Mode Only: On/Off** (runs `server-mode.sh on|off --no-services` — flips the mode/inhibitor/drainers/marker but NEVER touches tailscaled/jellyfin). Loading feedback: the dropdown tracks the in-flight action in `busyAction` ("mode"/"mode:nosvc"/"service:<name>", derived `busy`) — the affected pill swaps its glyph to `\uf013` and shows "Working…", the footer spinner appears, and the bar icon spins (RotationAnimation driven by a `spinAngle` property, `rotation: busy ? spinAngle : 0` so the server glyph always snaps upright when idle — a `Rotation { NumberAnimation on angle }` once froze at its last angle). The module polls status every 2s and has an optional (null-able) `tooltip`. Controlled by `scripts/server-mode.sh` (`status|on|off [--no-services]|service <name> <action>|config <key> <value>`):
  - **Sleep lock**: `on` starts a **transient user unit** `kmdot-server-mode` (`systemd-run --user --collect`) that runs `systemd-inhibit --what=sleep:handle-lid-switch --mode=block` wrapping `sleep infinity` — blocks suspend/hibernate/lid-close with NO root, so the laptop **never actually suspends** while serving; `off` stops the unit, releasing the lock. State marker at `~/.config/kmdot/server-mode`; sleep lock is the unit itself (marker is intent only). **The screen is left to the normal hypridle config**: hypridle keeps running (it is NOT a drainer), dims/locks/offs per `hypridle.conf`, then tries `systemctl suspend` — which the inhibitor refuses — so the laptop stays awake and serving while the screen looks asleep. Server mode is turned off ONLY explicitly (dropdown Turn Off pill).
  - **Services**: `on` runs `systemctl start tailscaled jellyfin`; `off` stops them. Needs the **polkit rule** (`config/polkit/90-kmdot-server-mode.rules`, install via the Commands table) or start/stop fail silently.
  - **Battery**: `on` suspends background drainers listed in `~/.config/kmdot/server-mode.conf` (`user_services`, `system_services`, `processes`): default `app-Handy@autostart.service app-blueman@autostart.service` / `docker.service containerd.service` / `kmdot-music uvicorn`. hypridle is NOT a drainer — it must keep running so the screen follows the normal config. Handy is started tray-only: `ensure_handy_hidden()` (in the script) self-creates a systemd drop-in (`~/.config/systemd/user/app-Handy@autostart.service.d/start-hidden.conf`) appending `--start-hidden` to the auto-generated unit's ExecStart. Because Handy usually runs DETACHED from its (inactive) autostart unit, `on` ALSO `pkill -x handy`s it — a leftover instance would pop its window on the next `off` (the single-instance handoff ignores `--start-hidden`, which is only honored on a fresh start). `off` restarts the systemd-managed ones (Handy fresh + hidden); killed processes are NOT restarted (can't reliably).
- **Screen**: there is NO server-mode screen management and NO watcher — `server-mode-watcher.sh` was deleted. The screen follows the normal hypridle config identically in BOTH modes: **lock at 5 min** (`loginctl lock-session` → hyprlock), **panel off at 6 min** (`hyprctl dispatch 'hl.dsp.dpms({ action = "disable" })'` — DPMS, not dimming: brightness would need restoring on wake, DPMS auto-restores), **suspend at 7 min** (`systemctl suspend`). The ONLY difference in server mode is that the **inhibitor** (Sleep lock bullet) refuses the suspend, so the machine stays awake serving with the screen off/locked. The wake is dual-path: hypridle's panel-off listener has an `on-resume` that runs `dpms enable` on ANY activity (mouse move, click, key press — hypridle sees activity even under hyprlock), and `appearance.lua` sets BOTH `misc:mouse_move_enables_dpms = true` AND `misc:key_press_enables_dpms = true` (this Hyprland version defaults both to `false`) as the compositor-side backup. The `on-resume` is the reliable path — button clicks and key presses alone don't trip the `mouse_move_enables_dpms` flag, which is why a server-mode session once came back from a hours-long screen-off to a dead panel that only a reboot fixed. Historically the mode had its own watcher (custom lock + DPMS-off after a `timeout`, wake on interaction, `screen` conf key, `screen_off` status); all of that was removed. `~/.cache/kmdot/server-screen-off` and the `timeout`/`screen` conf keys are stale leftovers and ignored.
- The dropdown: big On/Off toggle, per-service Tailscale (with Tailnet IPv4)/Jellyfin rows with Start/Stop pills, a battery blurb (drainers list), and a footer with sleep status (`inhibitor=active` from `systemctl --user is-active kmdot-server-mode` — "Sleep blocked" means the machine stays awake to serve) + refresh button. Status (`server-mode.sh status`) emits `mode|inhibitor|tailscale|tailscale_ip|jellyfin` key=value lines parsed by the module (2s poll) and dropdown (3s poll while open + after every action). Cross-closes with launchers and the other popups.

- **OpenCode theme hook**: writes the `theme` key to `~/.config/opencode/tui.json` (and `~/.local/share/opencode/kv.json` if present, since the `/themes` runtime pref can otherwise override it) via `theme-switcher/hooks/opencode.sh`. Applies on next opencode launch (no live reload).
- **Handy tray module**: `modules/Handy.qml` and `menu/HandyPopup.qml` live between OpenCode and Server Mode inside `HiddenModules`. Every end-of-recording path removes both binds, each toggle clears stale ones first, and the helper no-ops if no Recording window exists.
