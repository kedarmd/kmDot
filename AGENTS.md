# AGENTS.md

Dotfiles for a CachyOS + Hyprland workstation. Config files (not application code) — no build, no tests, no CI.

## Sync Model (Required)

- **Source of truth** is this repo: `config/`, `theme-switcher/`, `themes/`, `sync/`.
- **Never write directly** to `~/.config/*` or `~/.tmux.conf`. Edit the repo, then run `sync/<app>.sh`.
- Sync scripts (e.g. `sync/tmux.sh`) `rm -rf` existing config, `cp -r` from repo, then `ln -sf` to standard locations. Destructive.

## Commands

| Action | Command | Notes |
|---|---|---|
| Install selected apps | `./install.sh` | Requires `gum` (`pacman -S gum`). Multi-select TUI. |
| Single-app sync | `./sync/<app>.sh` | E.g. `./sync/nvim.sh`. Skips the TUI picker. |
| Uninstall | `./uninstall.sh` | Also requires `gum`. Removes symlink targets + kmdot copies. |
| Switch theme (CLI) | `theme-switcher/main.sh <theme>` | Themes: catppuccin, everforest, nord, onedark, tokyonight |
| Switch theme (quickshell launcher) | `config/quickshell/scripts/toggle.sh kmdot-theme` (Super+T) | Picks theme via quickshell launcher, calls `main.sh` (which restarts quickshell once) |
| Quickshell sync | `./sync/quickshell.sh` | Bar config lives in `config/quickshell/`. |

## Adding an App

1. Create `config/<app>/` with config files.
2. Create `sync/<app>.sh` (copy + symlink pattern — see existing scripts).
3. Add to `APPS` array in `install.sh` (and `uninstall.sh` if supported).

## Adding a Theme

1. Create `themes/<theme>/` with per-app config files matching each hook in `theme-switcher/hooks/`.
2. Theme hooks read from `~/.config/kmdot/themes/<theme>/`, not the repo directly.
3. Theme hooks reload the app after writing the config (e.g. `tmux source-file`).

## Key Quirks

- **Tmux**: prefix `C-s`; modular config in `config/tmux/conf.d/` (`00-base`, `10-bindings`, `20-theme`, `90-plugins`); TPM for plugins; UTF-8 locale required for Nerd Fonts.
- **Neovim**: lazy.nvim plugin manager; entrypoint `init.lua` → `require("options")` + `require("config.lazy")`.
- **Wallpapers**: theme-specific in `themes/<theme>/wallpapers/`; `cycle_wallpapers.sh` exits early if hyprpaper isn't running; active theme cached in `~/.cache/kmdot_theme`.
- **Quickshell**: top bar in `config/quickshell/`; colors are a `pragma Singleton` (`Colors.qml`, tokyonight default) regenerated from `themes/<theme>/quickshell.conf` by `theme-switcher/hooks/quickshell.sh`. That hook **restarts quickshell once** on theme change (Colors.qml is written first, then `pkill` + relaunch via `setsid nohup`), so the bar AND the launchers re-theme together and the launcher socket servers re-bind — live-reload on Colors.qml change would re-theme the bar but break the launcher sockets (they don't re-bind on reload), forcing a lazy restart on the next open. Not autostarted previously — autostart now launches `quickshell &`. Install with `sudo pacman -S quickshell` (cachyos-extra-v4).
- **Quickshell launcher**: Super+Space opens the app launcher on Overlay layer. All launchers are thin subclasses of `config/quickshell/components/LauncherBase.qml` (generic single-pane picker: search box, scored results list, footer, socket toggle, dim+card in ONE `PanelWindow` surface — see below for why). The card lives in the same surface as the dim so it can never be covered by it (layer-shell stacking of separate surfaces is creation-order dependent; separate dim windows ended up on top). `FloatingWindow` does NOT work for overlays (it maps as a normal tiled client). Launcher instances (declared in `shell.qml`, coordinated by `property var activeLauncher` so opening one closes the other):
  - `AppLauncher.qml` — sock `kmdot-launcher` (Super+Space). Search is a per-field matcher over `DesktopEntries.applications` (populates ~2s after launch; apps async — rebuild on signal): substring OR fuzzy-subsequence on `name`/`genericName`, substring-only on `execString`/`keywords`/`comment`/`id`. Do NOT fuzzy-match over fields concatenated into one haystack (a query like "files" then matches 21 apps by spanning unrelated words). Non-string entry fields crash `.toLowerCase()` with `TypeError: Property 'toLowerCase' of object is not a function` — string-coerce with `toStr()` (the old `(x || "")` guard does NOT catch non-string objects).
  - `menu/KmdotLauncher.qml` — sock `kmdot-kmdot` (Super+K): Applications / Connections / Keybinds / System / Themes. Nested launchers open via the coordinator.
  - `menu/SystemLauncher.qml` — sock `kmdot-system` (Super+Esc): Lock / Logout / Restart / Shutdown / Suspend (runs `hyprlock`, `hyprctl dispatch 'hl.dsp.exit()'`, `systemctl …`).
  - `menu/ConnectionsLauncher.qml` — sock `kmdot-connections`: Bluetooth (opens `bluetoothLauncher`) / Wi-Fi (opens `wifiLauncher`).
  - `menu/WifiLauncher.qml` — sock `kmdot-wifi` (bar Network module left-click): `nmcli` scan via `Process` + `SplitParser` (fields parsed right-anchored so SSIDs containing `:` survive; `nmcli -t` escapes them), active-first/signal-sorted list with block-glyph signal bars. Wi-Fi on/off is a **footer pill** (right-aligned, `footerActionActive` → `Colors.success` when on; triggered by click OR Tab), NOT a list item — toggling keeps the launcher open (optimistic `_state` flip, re-scan after 1.2s) and, since the radio caches APs lazily after re-enable, empty scans retry up to 2× at 2.5s before showing `emptyText`. While the scan is in flight the launcher shows the `loading` spinner + `loadingText`. Activate: active net → disconnect, saved net → `nmcli connection up`, open net → `nmcli dev wifi connect`, secured unsaved net → **password prompt** (LauncherBase `promptMode`: search input becomes a masked field, list swaps for a centered prompt; `connectProc` runs with `2>&1` into `SplitParser`, on non-zero exit re-prompts with the error). Uses `closeOnActivate: false` since the prompt flow must not close the launcher.
  - `menu/BluetoothLauncher.qml` — sock `kmdot-bluetooth` (bar Bluetooth module left-click): driven by the **native reactive `Quickshell.Bluetooth` service** (no Process/scan — unlike wifi). List from `Bluetooth.devices.values` sorted connected → paired → unpaired, subtitle shows Connected/Paired/Not paired (+ battery % when `batteryAvailable`), glyph mapped from the device's BlueZ `icon` string (`input-keyboard`→`\uf11c`, `input-mouse`→`\uf245`, audio→`\uf025`, phone→`\uf10b`, computer→`\uf109`, video-display→`\uf26c`, default→`\uf293`). Adapter power is the same **footer pill** pattern (`\uf293` on / `\uf011` off) — Tab toggles `adapter.enabled` (reactive, no optimistic flip needed). Discovery auto-starts on open and stops on close via the `onOpenedChange()` base seam (LauncherBase calls it on every `opened` change; subclasses must NOT re-declare `onOpenedChanged` or they shadow the base's focus-timer handler). Activate: connected → disconnect, paired → connect, unpaired → `pair()` then **auto-connect** once `paired` flips true (`_pairInFlight` set keyed by `dbusPath`, dropped on pair failure). Reactivity via `Connections` on `defaultAdapterChanged`/adapter `enabledChanged`+`discoveringChanged` (no `devices.countChanged` exists — the model is an `UntypedObjectModel` with no count signal; the pool refreshes at discovery start/stop transitions) plus per-device dynamic `d.<prop>Changed.connect(rebuild)` wired once in `rebuild()`. **blueman stays installed solely as the BlueZ pairing agent** (quickshell's service has NO agent support — PIN/passkey-confirming devices need blueman-applet running); bar + Connections no longer launch `blueman-manager`.
  - `menu/KeybindsLauncher.qml` — sock `kmdot-keybinds`: display-only (`deactivatable: false`) listing parsed from `config/hyprland/scripts/keybinds.lua` (a Lua shim that stubs `hl` and prints `KEY + combo   comment` from `keybinds.lua`).
  - `menu/ClipboardLauncher.qml` — sock `kmdot-clipboard` (Super+V): thin LauncherBase history picker backed by `scripts/clipboard-daemon.sh` (two `wl-paste --watch` watchers: default/text + `--type image/png`) and `scripts/clipboard-capture.sh` (both watchers can fire for one change, so capture + index/GC are `flock`-serialized and payloads are written atomically via `mv` — a racy `cp` once produced a CRC-corrupt PNG that Qt failed to decode in the launcher). Captures text and PNG clipboard payloads (hyprshot screenshots are automatic because hyprshot copies `image/png` via `wl-copy`), stores deduped SHA256 entries under `~/.cache/kmdot/clipboard/` (`index`, `text/`, `img/`, optional `thumb/` from ImageMagick), and prunes entries older than 1 day. Activate copies the entry back with `clipboard-copy.sh`; the footer Clear pill runs `clipboard-clear.sh` (history only, not the active clipboard).
  - `menu/ThemeLauncher.qml` — sock `kmdot-theme` (Super+T): lists themes via `Process` + `SplitParser` (NO `DirListing` API exists) from `scripts/list-themes.sh` (marks the active theme from `~/.cache/kmdot_theme`), runs `theme-switcher/main.sh <theme>` **detached** (`setsid nohup … </dev/null`) — mandatory: the quickshell hook pkills quickshell mid-run, and a live stdout pipe to a dying parent would SIGPIPE `main.sh` (`echo: write error: Broken pipe`). `refreshItems()` rebuilds `pool` on every open.
  - `modules/Backlight.qml` — brightness with an **optimistic + coalesced** setter (spawning a shell process per wheel tick drops steps, so scroll felt janky vs the Pipewire-based volume module): wheel updates the cached `cur` immediately for a smooth display, a single `Process` applies `brightnessctl set <target>`, and while a set is in flight the latest target is remembered (`_pending`) and applied on `onExited` so fast scrolls converge without dropping the last step; the 500ms poll only adopts the actual value when no set is in flight.
  - `menu/BatteryPopup.qml` — battery dropdown (sock `kmdot-battery`; bar Battery module **left-click** opens it via `toggle.sh`, **right-click** still cycles power profiles with `acceptedButtons: Qt.LeftButton | Qt.RightButton`). NOT a LauncherBase subclass: a transparent fullscreen `PanelWindow` overlay (no dim) with a card anchored top-right (top 48 / right 10). Header glyph (charge bolt `\uf0e7` + level icon) + % + status word; rate line (`changeRate` W) + time line (`timeToFull`/`timeToEmpty` via `formatTime` → "Xh Ym"); **power-usage graph** as a `Canvas` over UPower `GetHistory` charge history (script `scripts/battery-history.sh`: `gdbus call` `org.freedesktop.UPower.Device.GetHistory charge 43200 120` on the battery device object, NOT the root — parse caveats: output is single-line newest-first with `uint32 ` prefixes on the first tuple only; the sed extraction uses `s/^[^0-9]*([0-9]+)[^0-9]+([0-9.]+)[^0-9]+([0-9]+).*$/\1 \2 \3/p`; **reverse in QML** before plotting or the whole line draws off-canvas because `span` goes negative); points down-sampled to ≤90, oldest→newest, 0–100% Y with a 50% gridline, last-point dot + value label, start-time + "now" labels; 30s refresh timer while open. **Profile buttons**: three 1/3-width `PillButton`s (Power Saver / Balanced / Performance) that set `PowerProfiles.profile`; active one gets the workspace-style `Colors.border` fill + bold `Colors.text`, Performance is dimmed + disabled when `!PowerProfiles.hasPerformanceProfile`. Escape (focusTimer grabs focus on a plain `Item`, like the launchers' input) or clicking the fullscreen backdrop closes it; `open()` also closes `scope.activeLauncher` and LauncherBase's `openLauncher()` closes `scope.batteryPopup` — popup and launchers never coexist.
  - `components/PillButton.qml` — shared toggle/choice button matching the **active-workspace pill style** (see `modules/Workspaces.qml`: `Colors.border` fill + bold `Colors.text` when `active`, transparent + `text_alt` otherwise, hover → `text`, radius 8, `implicitHeight: 30`, NO outline border). Props: `active`, `enabled`, `text`, `glyph` (+ `glyphSize`/`textSize`), `clicked` signal. Used by the volume popup's "Sound/Mute" pill (`active: root.muted`) and the battery popup's power-profile pills.
  - `components/SliderBar.qml` — shared drag+wheel bar (0..1 `value`, `changed(v)` signal, `wheelStep`, track/fill colors + `barRadius`; no knob — the fill just ends flat). Track = `Colors.surface_alt`, fill = `Colors.primary`; `setFromX(x)` handles press+drag.
  - `menu/BrightnessPopup.qml` — brightness dropdown (sock `kmdot-brightness`; bar Backlight module **left-click** opens it, wheel still adjusts directly). Same fullscreen-overlay card pattern as the battery popup. Content: warning sun glyph (md-brightness_5/4/6/7 by level — PUA U+F00DE/F00DD/F00DF/F00E0, written as **literal characters**, NOT `\u` escapes, see below) + big `%` + "Brightness" label, then one big SliderBar. Reuses the module's optimistic+coalesced brightnessctl setter (`get`/`max`/`set`, `_applying`/`_pending`), 500ms poll while open; wheel on the card or bar steps ±2% of max.
  - `menu/VolumePopup.qml` — audio output dropdown (sock `kmdot-volume`; bar Audio module **left-click** opens it replacing pavucontrol, **right-click mute stays**). Lists output DEVICES from the native reactive `Quickshell.Pipewire` service, not pactl: `Pipewire.nodes.values.filter(n => n.isSink && !n.isStream)` — **`isSink` alone also matches app output streams** (`media.class` `Stream/Output/Audio`, e.g. `handy`, Zen → bogus 0% rows), so `!n.isStream` is mandatory. Rebuilt on open + a 3s timer while open (`Pipewire.onNodeAdded.connect(...)` is NOT QML-accessible — TypeError, no node-added signal). Sorted active-first (`n === Pipewire.defaultAudioSink`), then by description. Each row is a 64px two-line layout (10px top / 12px bottom margins, 8px spacing) so the active row isn't cramped: line 1 = type glyph (`device.api === "bluez5"` → md-bluetooth U+F00AF [literal char], name containing `hdmi`/`dp-`/`display` → `\uf26c`, else md-volume_high U+F057E [literal char]) + 6px primary dot on the active row + name (primary when active / `text_alt` otherwise, ElideMiddle, width-70) + `%` (muted/warning); line 2 = per-row SliderBar (width-26, height 11, vertically centered in the row) + mute glyph (`\uEEE8`/`\uf026`, warning when muted, `verticalCenterOffset: 0`) with its own MouseArea. On the active row the slider `trackColor` is `Colors.border` (not `surface_alt`) so the track stays visible against the row's `surface_alt` highlight. The list scrolls: ListView always `interactive: true`, height `min(sinks*72+8, 330)`, custom slim right-edge scrollbar; the row has NO onWheel (it would swallow wheel and kill scrolling — wheel over the SliderBar adjusts volume, wheel elsewhere flicks the list). Row click → `Pipewire.preferredDefaultAudioSink = row.n` (select output device); bar drag/wheel → `row.aud.volume`; mute glyph → `row.aud.muted`. Header = master bar (default sink, vertically centered) + right-aligned "Mute/Sound" `PillButton` (64px wide, 30px tall, vertically centered, `active: root.muted` — must share the Row's center or the pill looks high/low next to the slider). Caveat: bluez5 sinks can report `volume` 0 in quickshell even while playing (AVRCP absolute volume isn't in the Volume param the service reads) — the row shows 0% but audio still works; volume writes may not reach the device.
  - All three popups (Battery/Volume/Brightness) call `pickScreen()` in `open()`: a `Process` runs `hyprctl cursorpos` and sets the popup's `screen` to the `Quickshell.screens.values` entry containing that point, so the dropdown appears on the monitor where the module was clicked. Launchers still hard-code `Quickshell.screens.values[0]` (LauncherBase) and can open on the wrong monitor in a multi-screen setup.
  - `menu/CalendarPopup.qml` — calendar dropdown (sock `kmdot-calendar`; bar **Clock module left-click** opens it). Same fullscreen-overlay card pattern but **anchored `horizontalCenter`** (top 48) to sit under the center bar clock. Monthly grid (Su→Sa, 42 cells, 6×30px, `Colors.primary` fill for today / `surface_alt`+primary border for the selected day, 3px primary dot for days with events, out-of-month dimmed), prev/next chevron buttons, month-title header, divider, then a **day agenda** (selected date title + up to 6 event rows in **12-hour** "H:MM AM/PM - H:MM AM/PM title" or "All day" via `fmtTime12()`, "+N more" when capped, "No events" otherwise; the 112px time column never elides normal ranges so there are no dots after the hyphen; long titles elide but **hover starts a marquee** — a `clip: true` `Item` swaps the elided `Text` for a full-width `Text` that `NumberAnimation`s its `x` from the clip width to `-width` at `Math.max(1000, width*12)` ms, restarting on each re-enter, resetting on exit) and a footer Row: a muted "Synced HH:MM" status plus a clickable **Sync button** (border pill, refresh `\uf021` glyph / spin `\uf013` while loading) that calls `syncNow()` (`--force`). **Keyboard nav** (focusTimer grabs focus on the plain `Item`): arrows move the selection a day/week (crossing a month boundary follows it), `Keys.onPressed` + `event.key === Qt.Key_PageUp/Down` flip months (no dedicated Page handlers exist), Escape/Enter closes. **Google Calendar integration**: `scripts/calendar-sync.sh` curls the private iCal URL from `~/.config/kmdot/calendar-url` (first line; **NOT in the repo** — Google Settings → "Secret address in iCal format") into `~/.cache/kmdot/calendar.ics`, skipping the fetch when the cache is <30 min old unless `--force`; `scripts/calendar-events.mjs` (a **Node.js** script — no Python dependency, keeps the config barebones for laptops without Python; only requires Node) parses it to JSON grouped by `YYYY-MM-DD` (zero-dependency: implements its own bounded RRULE expansion for `DAILY/WEEKLY/MONTHLY/YEARLY` + `BYDAY`/`BYMONTH`/`BYMONTHDAY`/`INTERVAL`/`COUNT`/`UNTIL` — `FREQ=WEEKLY;BYDAY` expands every listed weekday per interval week, not just the DTSTART weekday; the expansion is bounded to the ±400d window, so an unbounded rule can't stall; TZID/`Z`/date-only handled via `Intl.DateTimeFormat` fixed-point offset resolution, `EXDATE` respected, multi-day all-day events listed on each day). The popup syncs at startup (`Component.onCompleted` → `syncNow()`, forced by `shell.qml`'s `Component.onCompleted: calendarPopup` touching the lazily-created property) and every 30 min via a repeating `Timer`; `open()` runs a stale-aware refresh then parses. No URL file ⇒ graceful: empty calendar, month grid still works. `pickScreen()` as above.
  - `LauncherBase` seams: `promptMode`/`startPrompt(title, error)`/`promptSubmitted(text)`/`exitPrompt()` turn the search input into a password field with a centered prompt + error line (footer hint + lock glyph swap in automatically); `closeOnActivate: false` makes `activate()` keep the launcher open so a subclass can decide (e.g. wifi password flow); `loading`/`loadingText` swap the `emptyText` ("No matches") for a spinner + message while the pool is being (re)built; `footerActionText`/`footerActionGlyph`/`footerActionActive` render a right-aligned footer pill that emits `footerActionClicked()` (Tab also triggers it — other launchers leave `footerActionText` empty; the footer hint elides to reserved space so it never runs underneath the pill, and the count text only takes its content width with a growing spacer pushing it to the right edge); The footer bar itself has **square top corners** — a 12px `Colors.base` strip is stacked at the footer's top to cover the `radius: 12` (a QML `Rectangle` can only round all four corners, so the strip is the square-top/rounded-bottom trick) — and the bottom corners stay radius-12 to match the card. `onOpenedChange()` is called on every `opened` change (subclasses use it to start/stop work tied to visibility, e.g. bluetooth discovery — do NOT re-declare `onOpenedChanged` or you shadow the base's focus-timer handler).
  - Toggled via a unix socket at `$XDG_RUNTIME_DIR/<sockName>.sock` (`SocketServer` + `handler: Socket { onConnectedChanged }` — note `onNewConnection` is a method, not a signal). All keybinds + bar clicks call `config/quickshell/scripts/toggle.sh <sockname>` (the app launcher alias is `launcher.sh`). `toggle.sh` **self-heals** if the socket is missing OR stale (file present but no server listening — quickshell died, or a live-reload from a manual Colors.qml edit unlinked the socket; the server won't re-bind on live-reload): `pkill -x quickshell || true` (the `|| true` is load-bearing — pkill exits 1 when quickshell is already dead, and `set -e` would abort before the restart), restart via `setsid`, wait for the socket to accept, then connect. A normal theme switch restarts quickshell in the hook, so self-heal is now a backstop.
  - `Quickshell.iconPath()` returns a working `image://icon/` URL usable in `Image`; `IconImage` is NOT available in this QtQuick. Delegate rows render a nerd-font `Text` glyph OR an `Image` icon (one or the other). **Glyph footgun**: QML `\uXXXX` string escapes take EXACTLY 4 hex digits — a 5-hex codepoint like `\uf075f` silently renders as U+F075 (fa-comment) + a literal `f`, and `\uf00de` renders as fa-xmark + `e`. PUA glyphs with 5 hex digits (e.g. md-bluetooth U+F00AF, md-volume_high U+F057E, md-brightness U+F00DE+; `md-volume_mute` U+F075F in `Audio.qml`) must be embedded as the **literal Unicode character**, or use 4-digit codepoints instead (`\uEEE8` fa-volume_xmark, `\uf026` fa-volume_off). Page keys: `Keys.onPressed` + `event.key === Qt.Key_PageUp/Down` (no dedicated handlers). Do NOT set `clip: true` on the card rectangle or the bottom corners square off — clip only the `ListView`. If the socket gets stale (previous instance died), `rm $XDG_RUNTIME_DIR/kmdot-launcher.sock` and restart quickshell — the server won't re-bind on live-reload.
